How to implement a rule

  1. Author a signature — a JSON file under data/waf_rules/<env>/<id>.json with id, name, category, severity, target, pattern, pattern_type, action, score. Generate them with examples/wslproxy-waf-demo/gen_waf_rules.py so JSON escaping is correct, or POST to /api/waf_rules.
  2. Or add a stage — a first-class control (like smuggling or jwt) is a (policy, ctx) → finding|nil function in api/waf_stages.lua, added to _M.PIPELINE and gated on a policy block so existing policies are unaffected.
  3. Bind to a policy — reference the signature id in waf_rules[] (and configure the stage block) of a data/waf_policies/<env>/<id>.json; validate against docs/waf-policy.schema.json with tools/waf_validate.py.
  4. Attach to a server — set waf_enabled, waf_policy_id and optional waf_mode_override on the vhost (or via the admin UI / bind_waf_policy MCP tool).
  5. Stage before you enforce — ship new blocking rules under signatures.stage (alarm-only until a date), watch the wafsec logs, then let them enforce.
