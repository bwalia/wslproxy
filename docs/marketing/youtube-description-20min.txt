────────────────────────────────────────
WHAT IS WSLPROXY?
────────────────────────────────────────
WSLProxy is a dynamic reverse proxy / API gateway built on OpenResty (nginx + Lua). Operators manage virtual hosts (servers) and rules that decide what happens to each request — proxy, redirect, static HTML, CAPTCHA, or block — evaluated live from JSON (or YAML) on disk (or Redis/Postgres). Only nginx server-block changes need a reload flag; rules and WAF stay hot.

FEATURES COVERED
────────────────────────────────────────
• Live rules — no OpenResty reload for rule / WAF / traffic-split changes
• Dynamic routing — priority + path specificity; geo, IP, JWT, S3 signing, cookies
• Response types — proxy (305), redirects, custom HTML, CAPTCHA (306), 403
• Traffic engineering — weights, canary promote/rollback, sticky cookie/header, least-conn
• Upstream health — passive (5xx) + active checks; fail-open when all unhealthy
• Per-server proxy timeouts — connect / send / read via balancer
• WAF — OWASP-style packs, anomaly scoring, monitor or block, events API
• Rate limiting — shared-dict burst / RPS on the hot path
• SSL — Let’s Encrypt auto-ssl, force HTTPS, ACME challenge locations
• Caching — static MIME/extension TTL, optional Varnish VCL, Docker blob disk cache
• Storage — disk JSON (request-path truth), optional Redis / PostgreSQL dual-write
• Config formats — JSON + YAML for servers/rules; admin API writes JSON
• Admin UI — servers, rules, upstreams, secrets, profiles, WAF policies/rules/events
• Next.js dashboard — logs, topology, AI-assisted log analysis
• REST + OpenAPI/Swagger — full CRUD for gateway objects
• MCP server — AI agents can validate config, CRUD, traffic, POPs/DNS
• wslproxy-cli — GitOps pull→push; `check nginx` in GitHub Actions / GitLab CI
• Version history & 4-eyes change requests — draft → pending → live
• Audit trail — NDJSON audit log
• Observability — traffic stats, Prometheus metrics, Grafana dashboards
• Local Docker — ./dev.sh (OpenResty + Redis + admin, hot-reload Lua)
• Production deploy — Ansible bare-metal/VM POPs; k3s wslproxy-ingress Helm chart
• Two-layer edge — outer POP + optional k3s ingress (tune timeouts on both)

────────────────────────────────────────
QUICK START
────────────────────────────────────────
# Local
./dev.sh

# CLI health / nginx check (CI-friendly)
docker run --rm \
  -e WSLPROXY_BASE_URL \
  -e WSLPROXY_TOKEN \
  ghcr.io/bwalia/wslproxy-cli:latest \
  check nginx -o json

# Config as files
wslproxy-cli pull -d ./cfg --resources servers,rules,waf
wslproxy-cli push -d ./cfg --yes --verify
