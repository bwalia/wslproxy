New · AI Gateway

OpenAI-Compatible Edge for LLMs

Put one secure, observable gateway in front of every model provider. Your apps speak the standard OpenAI API; WSL Proxy translates, routes, secures, and meters the traffic — Anthropic, OpenAI, or self-hosted Ollama behind a single endpoint.

What it is

A protocol-translating LLM gateway built into the proxy. Clients call the familiar OpenAI Chat Completions API; WSL Proxy rewrites each request into the target provider's native API (e.g. Anthropic Messages) and converts the reply back — including live token streaming (SSE) — so you never rewrite application code to switch or mix providers.

One endpoint, any model

Path-based rules route each call to the right backend, each with its own keys, rate limits, and WAF:

POST /api/claude  → api.anthropic.com   # OpenAI ↔ Anthropic
POST /api/openai  → api.openai.com
POST /api/llm     → ollama            # self-hosted

Use Cases & Benefits

Vendor-neutral apps

Write once to the OpenAI API and swap or blend Claude, GPT, and local models by configuration — no SDK changes, no lock-in.

Govern & secure centrally

Provider keys never touch client apps. Enforce JWT / API-key auth, WAF, and rate limits at the edge — per route, per team.

Control cost & latency

Route by model, weight, or canary; fail over between providers; send cheap/private work to self-hosted models and hard tasks to frontier models.

Observability & spend

Every prompt and response flows through one place — Prometheus metrics, audit logs, and per-model traffic stats for usage and cost visibility.

Streaming-native

Server-Sent Event token streams are translated chunk-by-chunk, so chat UIs stay real-time and responsive across providers.

Drop-in migration

Point your existing OpenAI base URL at the gateway. No payload rewrites — start mixing providers without touching client code.
